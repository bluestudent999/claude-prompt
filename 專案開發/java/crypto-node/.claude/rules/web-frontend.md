# 後台前端規範（crypto-node-web）

> **適用對象：** `crypto-node-web` 維運後台的前端。規格來源：`plan/crypto-node-web/spec.md`。
> 本文管**畫面與互動的硬要求**（框架無關）；串接與授權見 [`web-integration.md`](./web-integration.md)。
> **這些不是 UI 建議，是規格。** 每一條都對映 spec 的 R# / E#，寫錯會造成誤操作或資損。

---

## 1. 技術棧：Vue 3 + Element Plus（已決，2026-08-26）

| 項目 | 版本基準 |
|------|---------|
| 框架 | **Vue 3**（Composition API + `<script setup>`） |
| 元件庫 | **Element Plus** |
| 狀態管理 | **Pinia**（**不是** Vuex） |
| 建置 | Vite |

**決議理由**：組織既有的 Vue 心智模型直接可用（`cx-sports` / `crypto-payment` 兩個專案）、Element UI → Element Plus 有官方遷移對應、admin 生態 Vue 較強。**Vue 2 → Vue 3 是升級不是換框架**，這與「改用 React」是不同量級的決定。

> **為什麼不留在 Vue 2**：Vue 2 已於 2023-12-31 EOL。新專案選 EOL 框架＝第一天就欠一次升級，正是 `locked-decisions.md` D19 導入六角架構要避免的那件事。

### ⚠ 最高風險：抄到 Vue 2 寫法

**這與 Boot 3.5 誤抄 Boot 4 是同一類錯誤，而且更容易發生** —— 組織有兩個 Vue 2 專案在旁邊，網路上的 Vue 教學也大量是 Vue 2。

`web-reviewer` 的**第一個 CRITICAL 檢查項**就是這個。

| Vue 2（❌ 不可用） | Vue 3（✅） |
|---|---|
| Options API（`data()` / `methods` / `computed` 物件） | **`<script setup>` + Composition API** |
| `new Vue({...})` | `createApp(App)` |
| `Vue.component()` 全域註冊 | `app.component()` 或直接 import |
| `this.$refs.x` / `this.$emit()` | `ref()` / `defineEmits()` |
| `filters`（**Vue 3 已移除**） | computed 或一般函式 |
| `$listeners`（**Vue 3 已移除**） | 併入 `$attrs` |
| `.sync` 修飾詞 | `v-model:xxx` |
| `Vuex` | **Pinia** |
| `el-dialog` 的 `:visible.sync` | `v-model` |
| `element-ui` 套件 | `element-plus` 套件 |

**判不準某個寫法在 Vue 3 是否可用 → 查 Vue 3 / Element Plus 官方文件或直接跑起來驗證，不要憑印象。**

> **不要去改 `cx-sports` / `crypto-payment` 的 `vue2-patterns` 與 `vue2-coding-standards` skill** —— 那兩個專案仍在 Vue 2，那些 skill 對它們是正確的。本專案有自己的 [`/vue3-console`](../skills/vue3-console/SKILL.md) skill。

### 落點：同 repo（已決，2026-08-26）

`crypto-node-web` 位於 **crypto-node repo 內**，與 `crypto-node-service`、`crypto-node-flyway` 同層 —— 目錄名沿用既有模組命名慣例。

**為什麼同 repo 是對的**：前後端契約變更可以在**同一個 commit / MR** 完成。
> 反例就在組織內：`cx-sports` 的 Flyway 是獨立 repo，導致「改 sport 的人在自己 repo 看到全綠，卻不知道另一個 repo 的 migration 有問題」（見該範本的 `flyway-migration.md` §7.7）。同 repo 直接消除這類不同步。

**隨之而來、動工前要處理的事**：

| 項目 | 要做什麼 |
|------|---------|
| **`.gitignore`** | 加 `node_modules/`、`dist/`（前端建置產物）—— **不加就會有人把 node_modules commit 進去** |
| **建置鏈** | Vite 產物要不要進 Maven reactor / 打進 image？決定 `Dockerfile` 與 `deploy/` 怎麼改 |
| **CI** | 前端 lint / build 要進 pipeline，與後端同一個 stage 或獨立 |
| **commit scope** | 見 `git-workflow.md` —— 已新增 `web` / `web-api` |
| **跨模組變更** | 一個需求同時動 service + web 時，兩邊在同一個 MR，**不需要跨 repo 交叉引用** |

**§2 之後的所有規則框架無關**，選定 Vue 3 不改變它們任何一條。

## 2. 危險操作：二次確認 + 理由必填（R5、R6）

**七項危險操作**（這是完整清單，不得增刪）：

```
暫停掃描 · 恢復掃描 · 切換節點 · 重掃區間
地址移除 · 訂閱者停用 · 訂閱者恢復
```

每一項都必須：
1. **二次確認**
2. **理由必填，≥ 10 字**
3. **理由寫入操作紀錄**
4. 確認畫面**以白話說明後果與可逆性**

**明確不屬危險操作**（不得加上二次確認，那會讓日常操作變吵）：

```
拉取速率調整 · 通知網址登記 · 發測試通知
```

> **後果文案必須人審。** 例：「暫停掃描期間鏈上入金不會被記錄，恢復後會自動補上，不會遺漏」。
> **寫錯會誤導值班員做出反向處置** —— backlog 已把 T13a 標為「2 確認，後果說明文案必須人審」。

### 地址移除的額外要求（E13，M5 風險最高的操作）

移除前必須顯示該地址的**入金筆數與最近一筆時間**，確認畫面**完整揭露三項後果**：

1. 既有的交易與事件紀錄**不受影響、不會被刪除**
2. 此後該地址若再收到入金，**不會被記錄、不會產生事件、也不會有任何告警** —— 錢在鏈上到帳但系統中不存在（**靜默漏單**）
3. 該地址移除後**可被指派給其他租戶** —— 日後再收款將歸屬到別人，這正是 M5「租戶歸屬錯誤」的定義

**已有入金紀錄者，必須額外要求輸入該地址本身**作為二次確認（防選錯列）。

## 3. 三種狀態必須可區分（E1 / E10）

這是本專案**最容易犯的前端錯誤**：

| 狀態 | 畫面 | 絕不可 |
|------|------|--------|
| **取得失敗** | 「無法連線到 crypto-node，以下資料無法取得」 | ❌ **顯示空清單** —— 會被誤讀為「沒有資料」 |
| **確實沒有** | 「目前沒有 X」+ 下一步引導 | ❌ 空白畫面 |
| **有資料** | 正常渲染 | — |

**兩者的文案必須明顯可區分。**

> **為什麼容易錯：** 多數 HTTP client 的錯誤處理會回一個空集合，UI 照樣渲染成「目前沒有資料」。
> **對策：** 資料層就把「載入失敗 / 空 / 有資料」做成三個明確狀態，一路貫穿到元件，**不要用「陣列長度 0」表達兩種不同的事**。

## 4. 憑證明文只顯示一次（R9、R10）

**API Key 與簽章金鑰的明文只在產生當下顯示一次。** 此後任何畫面、清單、匯出、紀錄都不得顯示或記錄。忘記抄寫的唯一救濟是**輪替**。

### 前端的具體禁令

| ❌ 絕對禁止 | 為什麼 |
|---|---|
| 寫入 `localStorage` / `sessionStorage` / cookie | 明文會留在瀏覽器裡，違反「只顯示一次」 |
| 放進全域狀態管理（Vuex / Pinia / Redux…）的持久化層 | 同上，且 devtools 看得到 |
| 出現在網址（query string / hash） | 會進瀏覽器歷史與伺服器 log |
| 寫入 console / 前端錯誤回報 | 會外流到 log 系統 |
| 重新整理後還能取得 | 那就不是「只顯示一次」 |

**必須提供**：一鍵複製、明確的「關閉後無法再取得」警語、以及 E4 的**「立即輪替」入口**（未抄下就關閉畫面時的唯一救濟）。

**節點供應商網址內含憑證** —— 顯示時必須遮蔽（R10、AC-58）。

## 5. 租戶範圍在畫面上的體現（R2）

- 未指派的租戶**不得出現在任何清單、下拉選單或查詢結果**。
- **地址反查若命中範圍外的租戶** → 只顯示「不屬於你可操作的租戶」，**不得揭露是哪一個**。
- 權限不足的動作**不顯示按鈕**（而非顯示後點擊報錯）。

> ⚠ **但前端隱藏不是安全邊界** —— 後端必須重新判定（`web-integration.md` §5）。前端隱藏是 UX，後端過濾才是防線。**兩者都要做。**

## 6. 半成品狀態必須明示（R1a —— 最容易靜默出錯的一條）

OQ-8 決議「發憑證只限 Admin」，於是 Operator 會做出**看起來完成、實際不能用**的東西。

| 情境 | 畫面必須顯示 |
|------|------------|
| Operator 開通訂閱者後（無發憑證權限） | 「**尚待管理員發放憑證**」+ 通知管道；**不得看起來像已完成** |
| Operator 登記通知網址後、尚無簽章金鑰 | 「**尚待管理員產生簽章金鑰；在此之前下游無法驗證通知的真偽**」 |
| **測試通知送出成功** | **必須同時明示上述限制** —— 送達成功 ≠ 下游能驗簽 |
| 開通檢核清單 | 「API Key 已交付」與「簽章金鑰已交付」**兩項分別標示需管理員** |

> **② 那條最危險，因為它不會撞牆、只會靜默做出半成品**：Operator 全程沒有被擋，會合理認為設定完成，但**下游收到的門鈴沒有可驗證的簽章**。

## 7. 全體狀態 vs 單台狀態必須分區（R16、R17）

crypto-node 以**多台伺服器**運行。

| 類型 | 內容 | 呈現要求 |
|------|------|---------|
| **全體共用** | 掃描進度、落後量、是否暫停 | 全叢集一致，可直接呈現 |
| **單台** | 節點來源、已降級多久 | **必須標示「此為回應本次查詢的伺服器狀態」**，不得呈現為全體 |

> ⚠ **誤呈現會讓值班員以為節點已全數切換。**

**切換節點的畫面**（R17）必須：① 顯示各台目前的節點來源；② 執行後**逐台回報**結果；③ 明確指出「**全叢集是否已切換完成**」。

**過渡期**（服務端逐台能力交付前，R19③）：維持「顯示單台狀態 + 告知限制」，並明示「**全叢集切換請洽後端工程師**」。
**能力交付後必須同時移除這句** —— 否則系統說已完成、文案說去找工程師，指引互相矛盾。

## 8. 其他必須遵守的呈現規則

| # | 規則 | 來源 |
|---|------|------|
| 1 | **兩個時間分別標示**：「鏈上發生時間」（可能為空）與「我方記錄時間」，**不得混用**，也不得以前者作為篩選的唯一依據 | R18 |
| 2 | **地址匯入送出前**顯示「N 筆 → 租戶 X」確認；被拒的地址**逐筆列出含原因**，不得只回報「部分失敗」 | R8、E3 |
| 3 | **查詢結果過大必須分頁**並顯示總筆數，不得一次載入全部 | E11 |
| 4 | **非經本後台的變更**（下游 API、命令列）操作者顯示 `sys`、理由「非本後台操作」，**不得留空** | E9、E17 |
| 5 | 訂閱者停用後狀態**不得顯示為「已刪除」**（訂閱者不被刪除，僅停用） | E15 |
| 6 | 最後一名 Admin 被停用或降級 → **拒絕**，提示「系統至少需保留一名管理員」 | E6 |
| 7 | 非允許來源**在顯示登入畫面之前**就被拒絕，**不得洩漏帳號是否存在** | R13 |
| 8 | 第二因素**不得以 Email 自助重設**（Email 已是第一因素，自助重設會使第二因素失去意義）；只能由 Admin 重設 | E5 |

## 9. 前端不做的事

| ❌ | 為什麼 |
|---|--------|
| 自建業務資料的持久化快取 | 違反 R11「不得成為第二個真實來源」；快取是它最常見的偽裝 |
| 前端自訂確認數合法範圍、重掃區間上界 | 一律顯示**服務端回報的值**（E8、E14） |
| 對結果未知的操作自動重送 | E2 —— 重送危險操作可能重複執行 |
| 在前端計算「全叢集是否切完」 | 服務端尚未提供逐台能力（外部依賴②），自己猜就是編造 |
| 為未來的「下游客戶自助開通」預留入口 | Brief 明確 Out of Scope；留了會有人來填（對照 `coding-style.md` §8 投機性複雜度） |
| 把查詢類操作寫進操作紀錄 | R7 明訂查詢類不記錄，寫了會淹沒真正的變更紀錄 |
