# mock-rpc — 可腳本化的假 RPC

**Reorg、Failover、逾時、429、格式異常在真實測試網上無法按需觸發。** 這是很多團隊上線後才發現的問題。

Mock RPC 是**基礎設施，不是「有空再做」**：`S05` 就要交付，它是 I7 與 Failover 唯一可靠的驗證手段，也是整個測試策略的地基。

---

## 設計要求

| 要求 | 說明 |
|------|------|
| **可腳本化** | 一個測試能宣告「第 1~3 次呼叫回 A，第 4 次起改口回 B」，不需改 Mock 程式碼 |
| **可重播分叉** | 同一個 `blockNumber` 先後回不同 `blockHash`／不同 Log 集合 |
| **可注入故障** | 逾時、連線拒絕、HTTP 429、HTTP 5xx、回傳格式異常（缺欄位、型別錯、空陣列 vs null） |
| **多 provider** | 模擬主備兩個 endpoint，可個別控制其健康狀態以驗證 Failover |
| **可斷言呼叫** | 測試能驗證「呼叫了哪些方法、幾次、參數為何」——用來驗證沒有多餘的 RPC 呼叫（成本相關） |
| **確定性** | 同一腳本跑兩次結果相同，不依賴時間或亂數 |

## 必備情境腳本

### A. 確認深度（I7）

| 腳本 | 驗證 |
|------|------|
| `head` 緩慢推進，交易在區塊 N | 事件在 `head - N >= 該租戶確認數` 時才發出，早一塊都不行 |
| 兩租戶確認數不同（如 BSC:20 / BSC:32） | 各自在正確深度晉升，互不影響 |
| Receipt 重查回 `null` | **不發事件並告警**（不是轉 `reorged` —— D17 已取消） |
| Receipt 的 `blockNumber` 與 DB 不符 | 同上 |

### B. Failover

| 腳本 | 驗證 |
|------|------|
| 主 provider 連線拒絕 | 30 秒內切備援且**不漏塊**（S05 / P5 驗收標準） |
| 主 provider 回 429 | 退避後改用備援，不是無限重試打爆 |
| 主 provider 回 5xx | 同上 |
| 主恢復後 | 是否切回（或維持備援）—— 行為要明確且有測試 |
| 兩個 provider 都掛 | 掃描暫停、告警、**高度不後退**（I2） |

### C. 冪等與重掃（I6）

| 腳本 | 驗證 |
|------|------|
| 同一區間連續掃 3 次 | 交易列數與事件數不變 |
| 掃描中途拋例外 | 事務回滾，DB 無殘留（I1）；重啟後從正確高度續掃 |
| 同一區塊回傳重複 Log | 依 `(chain, tx_hash, log_index)` 去重（I4） |

### D. 資料異常

| 腳本 | 驗證 |
|------|------|
| Log 缺 `topics` / `data` 欄位 | 記錄並跳過該筆，**不中斷整批**、不寫入半筆 |
| 金額為 0 | 依 bigpicture §2.3 過濾（該段仍有效） |
| 未在白名單的合約位址 | 過濾 |
| 地址大小寫混雜 / TRON Base58 與 Hex 混用 | 正規化後仍正確歸屬（I9） |

### E. 負載（I10）

| 腳本 | 驗證 |
|------|------|
| 高密度區塊（每塊大量 Log） | 吞吐與記憶體；批次大小是否合理 |
| 訂閱者 B 補齊 15,000 筆 | A 的 P95 拉取延遲不受影響（S32） |

## 使用紀律

| ❌ | ✅ |
|---|---|
| 整合測試連真實 RPC | 慢、不穩、無法觸發異常。用 Mock RPC |
| 為了讓測試過而放寬 Mock 的真實度 | Mock 要模擬**真實會發生的事**，包括難處理的 |
| 只測順風路徑 | 故障路徑才是 Mock 存在的理由 |
| 腳本寫在測試方法裡硬編碼 | 腳本應可宣告、可重用、可組合 |
| 用 `Thread.sleep` 等待狀態 | 破壞確定性。用可控的時鐘或明確的觸發點 |

## 與真實網路的分工

| 層級 | 用什麼 | 驗證什麼 |
|------|--------|---------|
| 單元測試 | **真實主網交易的 fixture**（從瀏覽器抓原始 Log） | 解碼、地址轉換、精度換算的正確性 |
| 整合測試 `*IT` | **Mock RPC + Testcontainers PostgreSQL** | I1~I10 全部不變量 |
| 端到端 `*E2ETest` | 測試網真實 RPC + 小額轉帳 | 整條路真的通（不進 CI 預設流程） |

> **單元測試的 fixture 不要自己編。** 自己編的資料會不小心編成「自己的實作剛好會過」的樣子。抓真實的 USDT 轉帳 Log。
> **TRON 地址轉換以 100 組真實地址驗證**（S22 驗收標準）。
