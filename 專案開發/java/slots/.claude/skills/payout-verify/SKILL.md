# payout-verify — 實測案例回歸

**用法：** `/payout-verify`

回答一個問題：**拿參考站真的跑出來、有截圖佐證的盤面餵進去，我們算出一樣的金額嗎？**

對應 `spec.md` §1.1.3 **M-2**，以及 backlog 的 **T-09**（全案收斂點）與 **AC-3.9**。

> 測資本體在 `plan/reference-sampling.md`，**不要抄進這裡或測試註解** —— 標節號即可。

---

## Step 1 · 跑回歸測試

```bash
./mvnw -q test -Dtest='*PayoutRegression*' 2>&1 | tail -30
```

找不到這個測試類別 → **這件事本身就是缺陷**。M-2 沒有自動化，保真度就只能靠人眼。

---

## Step 2 · 盤點測資覆蓋

```bash
echo "=== reference-sampling 裡有截圖佐證的盤面 ==="
grep -nE "^###? S[0-9.]+|實測|截圖" plan/reference-sampling.md | head -20

echo "=== 測試引用到的節號 ==="
grep -rnoE "§S[0-9.]+" --include="*.java" src/test/ | sort -u
```

取樣紀錄裡每一個有完整三要素的盤面，都應該有一筆對應測資。

**納入測資的三要素（缺一不可）**：盤面 15 格看得清楚、下注參數看得到、派彩結果看得到。
只有其中一兩項就不要勉強推算補齊 —— **推算出來的測資比沒有更糟。**

---

## Step 3 · 算錯時的診斷順序

**不要先去改 spec 的賠率表。** 依序查：

1. **派彩公式** —— 對照 `spec.md` §1.4 的派彩規則，確認沒有多乘或少乘任何因子。
   > 若實際值剛好是預期的整數倍，八成就是多乘了某個因子。
2. **替代規則** —— WILD 作為替身時的計價方式（`spec.md` R-3）。
3. **線型軌跡** —— 少算或多算線時，逐條比對線型表（`spec.md` R-2）。
4. **最小連線長度** —— 不同符號門檻不同（`spec.md` R-1）。
5. **徽章加成** —— 加法與乘法的作用範圍（`spec.md` R-17.x）。
6. **幣別換算** —— `spec.md` R-6。

每一步都是去讀 spec 對照，**不是憑印象判斷**。

---

## Step 4 · 判定

| 情況 | 處置 |
|---|---|
| 任一案例算錯 | **block**。M-5 對派彩錯誤的容忍值是 0 件 |
| 找不到回歸測試類別 | **block**，要求建立 |
| 判定引擎跑不起來（需要資料庫或 Spring） | **block**，違反 `architecture.md` §4，也讓 M-2 與 RTP 模擬都無法自動化 |
| 取樣紀錄有新盤面但沒納入測資 | **warning**，要求補 |
| 實際值與 spec 不同，但確認是 spec 寫錯 | 改 spec（你有權），保留原文並註明改因，然後重跑 |
