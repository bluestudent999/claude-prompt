# 前端規範（遊戲畫面這一軌）

> 技術：Vue 3 + Vite + Uni-app 外殼，Cocos Creator 3.x 或 PixiJS 負責滾輪、粒子、骨骼動畫。
> 前端的職責只有一句話：**把後端算好的結果演出來。**
>
> 要做出什麼畫面行為，看 `plan/yummy/spec.md` `AC-8.x` 與對應的 Flow。這份只管邊界。

---

## 1. 紅線：前端不算錢

前端不得出現任何金額或勝負計算 —— 賠率、線型、連線判定、替代規則、徽章、RNG、觸發機率，一項都不行（不變量 I1、`spec.md` R-10）。

**允許的只有**：把後端回傳的矩陣轉到對應位置、依後端給的中獎線畫高亮、把後端給的金額跑分演出來。

> 檢查方式：在前端程式裡搜賠率數字與線型陣列。**搜得到就是破線。**

---

## 2. 動畫與入帳的關係（最容易漏的地方）

派彩由後端自行完成，**不以前端回報為條件**（不變量 I3、`spec.md` R-7 鐵則）：

- 前端可以回報「動畫播完了」，但那**不能是入帳的唯一觸發**。玩家中途關瀏覽器，錢照樣要進去。
- 前端重複回報不得造成重複入帳 —— 靠後端的單局冪等擋（I4）。
- 前端**不得**因為「還沒播完」而隱藏或修改金額。跑分只是視覺效果，數字來自後端。
- 前端**不得**在關閉頁面時送「取消派彩」之類的請求。

---

## 3. 狀態保留

免費旋轉序列、BONUS 選箱這類跨多局的流程，玩家中途離開後要能還原（`spec.md` E-9、`AC-10.11`、`AC-10.25`）。

**狀態的真實來源在後端。** 前端可以快取，但重新進入時一律以後端為準 —— 前端 localStorage 的狀態不得覆蓋後端狀態。
