# 架構與系統邊界

> 執行環境：**Java 21 + Spring Boot 3.5**（企劃書只寫「Java 最新穩定版本」，本範本比照庫內其他 Java 範本定為 3.5）。
> 資料：MySQL（遊戲自己的資料）+ Redis（彩池即時值、工作階段、下注鎖）。
> 前端：Vue 3 + Vite + Uni-app 外殼，Cocos Creator 3.x / PixiJS 渲染。
>
> 這份只寫**邊界**。業務流程看 `plan/yummy/business-logic.md` §3～§4，命名風格看 `rules/coding-style.md`。

---

## 1. 最重要的一條邊界：前端不算錢

```
玩家點「開始」
    │  前端送出的只有意圖：下多少、幾條線、冪等鍵
    ▼
後端  開獎 → 判定 → 算錢 → 扣款派彩 → 寫日誌
    │  回傳的是既定結果：矩陣 + 中獎線 + 派彩金額
    ▼
前端  把滾輪轉到指定位置，播動畫
```

**硬規則（不變量 I1）：**

- 前端不得有任何金額或勝負計算。
- 後端不得信任前端送來的結果類欄位。只接受意圖類欄位。
- **「這局中了多少」只有一個地方算得出來。** 有第二個地方算，遲早不一致。

> 判準：**把前端整包換成一個亂寫的程式，後端的帳仍然必須完全正確。**

---

## 2. 餘額不在遊戲這邊

錢包屬平台，遊戲不得自建餘額儲存（不變量 I2、`business-logic.md` §2）。

| 資料 | 放哪 |
|---|---|
| 玩家餘額 | **平台錢包（外部系統）**，只能透過介面查／扣／派 |
| 投注紀錄、開獎日誌 | 本專案 MySQL（留痕，I7） |
| 彩池即時值、工作階段、下注鎖 | Redis |

> 最早那份 `Yummy_Slot_Development_Plan.md` §2.3 寫「MySQL 儲存帳戶餘額」，
> 那是後續文件已經取代掉的說法（`business-logic.md` §2 把錢包列為外部角色）。**以後者為準。**

## 3. 通訊分工

| 走哪 | 用途 |
|---|---|
| **REST** | 身分驗證、記錄查詢、規則查詢 |
| **WebSocket (WSS)** | 彩池數值跳動、即時下注開獎 |

**紅線**：不論走哪條路進來，**扣款與派彩必須共用同一條後端路徑**。兩條協定各自實作一份結算 = 兩份會漂移的真實來源。

## 4. 模組邊界

依業務職責切，彼此不伸手進對方內部實作。對應 `backlog.md` 的任務分組：

| 模組 | 對應任務群 |
|---|---|
| 判定引擎（線型、連線、替代、徽章） | A 群 T-05~T-09 |
| 啟動與下注 | B 群 T-01~T-04 |
| 資金交易（扣款、派彩、異常補償） | C 群 T-10~T-12 |
| 批量 | D 群 T-13 |
| 彩池 | E 群 T-14~T-17 |
| 記錄與獎勵事件 | F 群 T-18~T-20 |
| 前端表現、營運參數 | G 群 T-21~T-23 |
| BONUS 小遊戲 | H 群 T-24~T-27 |
| 免費旋轉 | I 群 T-28~T-32 |

### 判定引擎必須能單獨跑

**給它一個盤面矩陣 + 下注參數，就要能吐出金額** —— 不需要資料庫、不需要錢包、不需要 Spring。

這不是潔癖，是兩件事的前提：
1. **M-2 實測回歸**（T-09）要自動化。
2. **RTP 模擬**要跑得動 100 萬局。

綁上框架，這兩件都做不到。backlog 也是這樣切的：A 群標明「純規則，不依賴任何外部系統」，可與其他線完全平行。
