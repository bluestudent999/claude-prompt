# 複製保真度：依據要追得回去

> 這個專案的成敗指標是「複製得準不準」（`plan/yummy/spec.md` §1.1.3，M-1 目標 100%）。
> 要能驗證這件事，唯一的辦法是：**每一條玩法規則，都指得出它的依據在哪。**
>
> 注意這條規則**不是禁止你做事**。規則要怎麼訂、要不要跟參考站不一樣，你都可以決定（`rules/plan-authority.md`）。
> 這裡只要求一件事：**決定完要寫下來、指得出來。**

---

## 1. 規則住在哪

| 文件 | 放什麼 |
|---|---|
| `plan/yummy/spec.md` | **實作的唯一依據。** 業務規則 `R-*`、邊界 `E-*`、驗收條件 `AC-*` |
| `plan/yummy/business-logic.md` | 角色、資料流、Flow-A~G、規則的來龍去脈 |
| `plan/reference-sampling.md` | 參考站取樣事實（`§S*`），是 spec 的上游依據 |
| `plan/yummy/backlog.md` | 32 顆 T 任務，每顆標了 `Required Spec Sections` |

**不要在 `.claude/` 或程式註解裡複述規則內容。** 賠率、線型、符號、公式一律去讀 spec。
抄一份就是多一個會過期的來源，而 M-1 最怕的就是有兩份不一樣的規則。

---

## 2. 實作時只有一個動作：標依據

每一條玩法規則的實作旁，標出它對應的 spec 編號：

```java
// spec.md §1.4 R-3（WILD 替代，按被替代符號計價）
```

規則若是我方自訂（參考站沒有、或刻意不照抄），spec 那條會有 `🔧 自訂` 標記，照樣標編號即可。

**標不出編號代表兩種情況之一**：

| 情況 | 怎麼辦 |
|---|---|
| spec 有這條，只是你沒查 | 去查，補上編號 |
| spec 根本沒有這條 | **你自己補進 spec**（`plan-authority.md` §2），然後標編號 |

**沒有第三種。** 不會出現「要回去問企劃」——企劃就是你。

---

## 3. 業務規則的三個來源，標記方式不同

spec 裡的規則不是同一種東西，混在一起會讓 M-1 失去意義：

| 來源 | 意思 | 算進 M-1 對拍嗎 |
|---|---|---|
| **取樣驗證** | 參考站截圖看得到，或已用實測盤面驗證 | ✅ 算，要 100% 一致 |
| **我方自訂**（spec 標 `🔧`） | 參考站看不出來，或我們刻意改 | ❌ 不算，本來就沒有對照組 |
| **營運參數** | 權重、機率、比例、RTP 目標這類數值 | ❌ 不算，這些是可調的，不是要複製的規則 |

> `business-logic.md` §5 已經做過這個切分：**可觀察的照抄，不可觀察的自訂。**
> 符號權重、彩池注入比例、觸發機率這類東西從截圖本來就看不出來，**也不需要看出來** ——
> 它們是 brief §2.2 V-2「數值自主」要的東西，硬去猜參考站的數字既做不到也沒意義。

---

## 4. 三種保真度驗證

| 指標 | 驗什麼 | 怎麼驗 |
|---|---|---|
| **M-1** 規則對拍 | 每條「取樣驗證」類規則的實作與 spec 一致 | 每條規則一個測試，測試標 spec 編號 |
| **M-2** 實測回歸 | 參考站實際跑出來的盤面，我們算出同樣金額 | 自動化回歸測試（對應 T-09、`AC-3.9`） |
| **M-3** 畫面行為 | UI 行為與截圖一致 | 對照檢查表人工過（對應 `AC-8.x`） |

M-2 的測資來源是 `reference-sampling.md` 裡有截圖佐證的盤面。**每多取樣一個，就多一筆測資。**

納入測資的條件（三者缺一不可）：盤面 15 格看得清楚、下注參數看得到、派彩結果看得到。
只有其中一兩項就不要勉強推算補齊 —— 推算出來的測資比沒有更糟。
