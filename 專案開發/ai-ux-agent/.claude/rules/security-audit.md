# 安全、憑證與證據完整性規範

> 本文規範 AI UX Audit Platform 的憑證管理、日誌脫敏、證據完整性，以及對目標站的負責任存取。

---

## 1. 憑證與 Secret 管理（硬性紅線）

- 登入帳密、API Key、Token 等 secret **一律**由環境變數 / `.env`（**必須** gitignore）注入，程式以環境變數讀取。
- **嚴禁**明碼寫入任何進版控的檔案（含程式碼、設定、測試、plan、報告、commit 訊息）。
- 憑證只允許出現在 **Adapter / 設定層**，**不得**進入 Core / Domain 或任何日誌（對映 architecture §2 依賴紅線、OQ-4 憑證管理）。
- 憑證缺失（環境變數未設）時，**不啟動**登入 Task，明確報錯並於報告註明「未提供憑證，僅完成 Visitor 範圍」（dev-plan §2.6）。
- `➡️ defer-to-dev`：secret 實際注入機制（`.env` 載入器 / secret store）。

---

## 2. 對目標站的負責任存取

- 僅對**利害關係人指定且已授權**的目標站執行審計（E1 = `https://sports-2.cxsport.net/`，需登入後審計）。
- **禁止**對目標站做壓測、DoS、大量並發請求或掃描類行為 —— 本專案不做壓力測試、不做資安掃描（Spec §4 Out of Scope）。
- 目標站不可達 / 逾時：**中止本次審計，不產半套結論**，明確報「目標站不可達」（dev-plan §2.6）。

---

## 3. 證據完整性（Evidence Integrity）

> 對映產品最高紅線「證據優先」。證據是審計結論的唯一依據，必須可信、可追溯。

- 每筆 `Observation` 落地時保留穩定路徑與擷取當下的頁面識別（URL / 狀態），供 Issue 引用與人工複核。
- **禁止**偽造、後製或推測證據；`Issue.Evidence` 必須指向**真實擷取**的 Observation。
- 失敗情境（登入失敗、Session 逾時、API 逾時）也要**留存失敗證據**（失敗截圖 / 錯誤訊息），不得靜默（dev-plan §2.6）。

---

## 4. 日誌脫敏

- Log **禁止**印出明文帳密、Token、Cookie、session 值，或完整請求體中的敏感資料。
- 需輸出含敏感欄位的物件時，先以遮蔽工具將 secret 欄位轉為 `******`。
- 報告與截圖若可能含登入後的個資，落地前應評估是否需遮蔽（`➡️ defer-to-dev`：遮蔽策略）。

---

## 5. 推理輸入 / 輸出的注入防護

- 送入 LLM 的頁面內容視為**不可信外部輸入**；不得讓頁面文字覆寫系統指令（prompt injection 防護）。
- LLM 產出的 Issue 在寫入報告前，必須通過 §3 證據連結檢查與四欄位驗證（見 architecture §4），**不得** Fail-Open（放行無證據結論）。
