# 多語系（第一期 5 語系：簡中、繁中、英、越、菲律賓文）

> **前台介面字串不在本 repo。** H5／App 的按鈕、選單、提示由另一部門自翻。本 repo 負責的是**資料名稱回退**、**分類名稱自譯表**、**通知與簡訊文案**、**後端錯誤訊息**，以及把語言正確傳進每一層。
> 來源：Brief §4 In 第 12 條、Spec-2 R2、Spec-3 R64、dept-assignment 規則 1～3、Spec-4／5（後台只中文）。

---

## 1. 語言碼與標頭

| 語言 | 碼 | 框架常數 | 說明 |
|------|----|---------|------|
| 簡體中文 | `zh` | `constants.ZH` | 供應商欄位 `name_zh` |
| 繁體中文 | `zht` | **本專案自訂**（`platform/i18n.ZHT`） | 框架 `constants.Languages` 沒有繁中；要在 `platform/i18n` 註冊，否則框架 middleware 會回退英文 |
| 英文 | `en` | `constants.EN` | 預設與最終回退 |
| 越南文 | `vi` | `constants.VI` | — |
| 菲律賓文（他加祿語） | `tl` | `constants.TL` | 供應商是否提供名稱未確認（Brief §7 第 2 項） |

| 規則 | 說明 |
|------|------|
| 標頭 | `x-lang: <碼>`；框架 `RecoverMiddleware` 放進 context（`constants.HeaderLang`）；缺省 `en` |
| 不在清單的碼 | 視為 `en`，不報錯，記 `sp_i18n_unknown_lang_total` |
| 會員已登入 | 會員設定的語言**優先於** `x-lang`（Spec-3 設定頁「登入後帳號偏好優先」）；由 `member` 包的 middleware（Sort 300）覆寫 context |
| 後台 | **只有中文**（dept-assignment 預設 1）：`/api/admin/**`、`/api/operator/**` 忽略 `x-lang`，固定 `zht`；後台的繁簡由前端處理，不算翻譯 |
| WebSocket | 握手 query `lang=`；推送的資料名稱已回退，client 不重做 |

## 2. 資料名稱回退（Spec-2 R2）

聯賽、球隊、球員、賽季、教練、場地的名稱來自供應商，存在 `league/team/player/...` 的多語欄位（`name_zh`、`name_zht`、`name_en`、`name_vi`、`name_tl`、`name_raw`）。

**回退順序（`platform/i18n.ResolveName(ctx, names)`）：**

| 會員語系 | 順序 |
|----------|------|
| `zh` | zh → zht → en → raw |
| `zht` | zht → zh → en → raw |
| `en` | en → raw |
| `vi` | vi → en → raw |
| `tl` | tl → en → raw |

| 規則 | 說明 |
|------|------|
| 繁簡互備 | 繁簡互備時**不做簡繁轉換**，直接用對方欄位（供應商兩者都有時各自正確；只有一邊時寧可顯示另一邊也不機翻） |
| 空值 | NULL 或空字串視為沒有（collector 不填英文進去，`thesports-ingest.md` §7） |
| API 回應 | **只回回退後的單一字串 `name` + `name_lang`（實際用了哪個語言）**；不回整包多語（`api-contract.md` §2 第 6 條） |
| 搜尋 | 比對**所有語系欄位與英文**（Spec-3 R45），結果顯示仍走回退 |
| Redis 快照 | 快照存**多語欄位**，回退在 `api` 回應時做（同一份快照服務所有語系） |

## 3. 分類名稱自譯表（Spec-2 R2、S2-T2）

供應商以代碼回傳的分類，平台自譯 5 語系：

| 類別 | 例 | 表 |
|------|----|----|
| 比賽狀態 | 未開賽、進行中、中場、完場、延期、取消、中斷、腰斬、待定 | `category_i18n(kind='match_status')` |
| 事件類型 | 進球、點球、烏龍、黃牌、紅牌、兩黃一紅、換人、VAR、進球取消 | `kind='event'` |
| 統計項 | 控球率、射門、射正、角球、傳球成功率… | `kind='stat'` |
| 天氣、位置、傷停原因類別、轉會類型、能力類型、榮譽類別、賽事階段 | — | 各自 `kind` |

| 規則 | 說明 |
|------|------|
| 鍵 | `(kind, code)` 唯一；值是 5 語欄位 + `en` 必填 |
| 回退 | 缺語系 → `en` → `code` 原文 |
| 維護 | 總控後台可編輯（Spec-4）；程式碼**不得**寫死中文字串當分類名 |
| 快取 | 框架本地快取 + `cache-refresh` 廣播；改表後 5 秒內生效 |
| 新代碼 | collector 遇到表裡沒有的 `code` → 存 `code` 原文並記 `sp_i18n_unknown_code_total{kind}`，**不丟資料** |

## 4. 通知、簡訊、後端錯誤訊息（Spec-3 R64）

| 類型 | 位置 | 規則 |
|------|------|------|
| 站內通知文案 | `internal/platform/i18n/locales/<lang>.json`，key `notice.<type>.<field>` | PM 先定中文版（dept-assignment 規則 8），翻譯補 5 語；**程式碼只用 key**，`i18n.LoadByLang(lang, &i18n.Index{Prefix:"notice", Key:"goal.title", Default:"...", Args:[...]})` |
| 推播標題與內文 | 同上，`push.<type>.*` | 依**收件裝置**的語言，不是發送當下的 `x-lang` |
| 簡訊 | `sms.<type>` | 依會員語系；供應商要求的字數上限由 provider 介面檢查 |
| API 錯誤 `msg` | `error.<code>` | `apierr` 的 `ErrorCode.Msg` 是 default（英文）；框架依 context 語言翻譯 |
| 後台 | 只中文，`zht.json` 必有、其他可缺 | — |

| 規則 | 說明 |
|------|------|
| 檔案 | `locales/{zh,zht,en,vi,tl}.json`，以 `embed.FS` 內嵌，`i18n.InitBundle` 載入；**`en.json` 缺 key 啟動失敗**（框架要求預設語言齊全） |
| key 命名 | `<prefix>.<type>.<field>`，小寫點分；不含空白與中文 |
| 參數 | `{}` 佔位依序替換（框架 `Args`）；不要用 `%s` |
| 新增 key | 先加 `zh.json` 與 `en.json`（中文版與英文 default），其餘語系**批次送翻**（§6） |
| 測試 | `internal/platform/i18n/locales_test.go`：五檔 key 集合一致（缺的列出，不是失敗；`en` 缺才失敗）、`{}` 數量一致 |

## 5. 名稱與文案在各層的責任

| 層 | 做什麼 | 不做什麼 |
|----|--------|---------|
| collector | 原樣存供應商多語欄位 | 不回退、不翻譯 |
| dao | 讀多語欄位 | 不回退 |
| service | 呼叫 `i18n.ResolveName`、`i18n.LoadByLang` | 不自己 `switch lang` |
| controller／dto | 回 `name` + `name_lang` | 不回整包多語 |
| `web/admin` | 固定中文 | — |

## 6. 翻譯批次流程（dept-assignment 規則 3）

| 階段 | 本 repo 要做什麼 |
|------|----------------|
| S3-T6 字串框架（W6）前 | 新 key 只填 `zh` 與 `en`；其他語系留空；開發與自驗用中文 |
| 每波結束 | `/contract-export` 順帶產 `docs/i18n/pending-<wave>.csv`（key、zh、en、空的語系），PM 送翻 |
| 翻譯回來 | 匯入對應 `<lang>.json`，跑 §4 測試；由 P-10 母語審校 |
| 正式翻譯的 12 張 ticket | S2-T2、S3-T1、S3-T2、S3-T6、S3-T12～T16、S4-T14、S6-T5、S6-T7：這些 ticket 的 DoD 含 5 語 key 齊全；其他 ticket 只卡最終驗收 |
