# sec-verify — 回歸驗證

**用法：** `/sec-verify <上次報告路徑>`

---

## 這個 skill 在回答什麼

**上次報的那些，現在還在嗎？** 以及 —— **修的過程有沒有弄出新的？**

---

## 步驟

1. 讀上次的 `report.md` 與 `findings/`。
2. 逐條複驗。每條 finding 都附了「改完怎麼確認」的指令（`rules/report-standard.md` §2），先跑那個：
   ```bash
   （finding 裡的定位指令）
   ```
3. 跑完指令還要**讀程式碼確認**：指令沒命中不等於修好了，可能只是換個寫法。
4. 對「已修復」的，檢查**修法有沒有製造新問題**（最常見：為了修 A 而繞過 B 的檢查）。
5. 產出對照表。

---

## 判定

| 狀態 | 意思 |
|---|---|
| **已修復** | 原路徑不成立，且修法沒製造新問題 |
| **部分修復** | 主路徑擋了，但同類問題在別處還在（列出還在的位置） |
| **未修復** | 原樣 |
| **退步** | 修的過程弄出新問題，或原本擋著的防線被拿掉了 |
| **無法驗證** | 需要的資訊不足（寫明卡在哪） |

---

## 紀律

- **不要因為對方說修好了就標已修復。** 要自己驗。
- **退步項目要放在顯眼處。** 修出新問題比沒修更需要立刻知道。
- 驗證期間一樣不改標的程式碼、不碰執行中系統。
