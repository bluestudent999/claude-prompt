# sec-quick — 單軸快掃

**用法：** `/sec-quick <軸>`

軸名：`隔離` ｜ `繞過` ｜ `權限` ｜ `金流` ｜ `注入` ｜ `機密` ｜ `依賴`

---

## 跟全面掃描的差別

| | 全面掃描 | 單軸快掃 |
|---|---|---|
| 盤點 | 七項全盤 | **只盤這條軸需要的**（通常是入口清單 + 該軸的機制位置） |
| 掃描 | 六個 auditor | 一個 |
| 驗證 | 照跑 | **照跑，不能省** |
| 產出 | 完整八章報告 | 單軸簡報 + finding |

> **驗證階段不能因為是快掃就省。** 省掉它，誤報照樣會摧毀可信度。

---

## 步驟

1. 讀 `scan-target.md` 確認標的與模式。
2. **精簡盤點**：只盤這條軸要用的東西。
   - `隔離` → `platformId` 怎麼取、有無 AOP 覆寫、對外入口清單
   - `繞過` → 所有 filter／攔截器的註冊順序、URL pattern、提早放行分支
   - `權限` → 認證授權實作在哪幾層、對外入口清單
   - `金流` → 會異動餘額的路徑、鎖的位置
   - `注入` → `${}` 清單、上傳與外連的位置
   - `機密` → 設定檔清單、log 與例外處理位置
   - `依賴` → `pom.xml` 直接依賴
3. 派對應的 auditor。
4. 派 `finding-verifier` 驗每一條。
5. 產出簡報：

```markdown
# 快掃：<軸> — <標的> <日期>

## 掃了什麼（範圍與抽樣方式）
## Finding（通過驗證的）
## 待查
## 已排除（理由不直觀的）
## 本次限制
```

---

## 紀律

- 使用者要快掃就**不要擅自升級成全面掃描** —— 1,610 個 Java 檔，燒 token 又拖時間。
- 快掃發現高嚴重度問題 → **照樣只交這一軸**，但在回報中建議「這條軸的問題可能延伸到其他軸，
  建議跑 `/sec-scan`」，由使用者決定。
- 抽樣了就要寫明抽樣方式與比例。
