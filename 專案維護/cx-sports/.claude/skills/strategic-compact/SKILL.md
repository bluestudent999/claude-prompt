# 策略性壓縮 Skill

在你的工作流程中的策略性時間點建議手動 `/compact`，而非依賴任意的自動壓縮。

## 啟用時機

**任務開始前應主動壓縮：**
- 大規模重構（跨多檔案）
- 跨多個檔案的功能實作
- 複雜互動的除錯

**不需要提前壓縮：**
- 單一檔案編輯
- 簡單錯誤修正
- 文件更新

**工作階段中途應壓縮：**
- 執行長時間工作階段接近上下文限制時（200K+ Token）
- 進行多階段任務時（研究 → 規劃 → 實作 → 測試）
- 在同一工作階段中切換不相關的任務
- 完成重大里程碑後開始新工作
- 回應變慢或不那麼連貫時（上下文壓力）

## 為何需要策略性壓縮？

自動壓縮在任意時間點觸發：
- 經常在任務中途，遺失重要的上下文
- 不感知邏輯的任務邊界
- 可能中斷複雜的多步驟操作

在邏輯邊界進行策略性壓縮：
- **探索完畢、執行之前** — 壓縮研究上下文，保留實作計畫
- **完成里程碑之後** — 為下一階段重新開始
- **重大上下文切換之前** — 在執行不同任務前清除探索上下文

## 運作方式

`suggest-compact.js` 腳本在 PreToolUse（Edit/Write）時執行，並：

1. **追蹤工具呼叫** — 計算工作階段中的工具呼叫次數
2. **閾值偵測** — 在可設定的閾值時建議（預設：50 次呼叫）
3. **定期提醒** — 閾值後每 25 次呼叫提醒

## Hook 設定

新增至你的 `~/.claude/settings.json`：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit",
        "hooks": [{ "type": "command", "command": "node $CLAUDE_PROJECT_DIR/.claude/skills/strategic-compact/suggest-compact.js" }]
      },
      {
        "matcher": "Write",
        "hooks": [{ "type": "command", "command": "node $CLAUDE_PROJECT_DIR/.claude/skills/strategic-compact/suggest-compact.js" }]
      }
    ]
  }
}
```

## 設定

環境變數：
- `COMPACT_THRESHOLD` — 首次建議前的工具呼叫次數（預設：50）

## 壓縮決策指引

使用此表格決定何時壓縮：

| 階段轉換 | 壓縮？ | 原因 |
|----------|--------|------|
| 研究 → 規劃 | 是 | 研究上下文龐大；計畫是濃縮的輸出 |
| 規劃 → 實作 | 是 | 計畫在 TodoWrite 或檔案中；釋放上下文給程式碼 |
| 實作 → 測試 | 視情況 | 若測試參考最近的程式碼則保留；切換焦點時壓縮 |
| 除錯 → 下一功能 | 是 | 除錯追蹤會污染不相關工作的上下文 |
| 實作中途 | 否 | 遺失變數名稱、檔案路徑和部分狀態的代價很高 |
| 失敗嘗試之後 | 是 | 嘗試新方法前清除死路推理 |

## 壓縮後保留的內容

理解什麼會被保留有助於你自信地壓縮：

| 保留 | 遺失 |
|------|------|
| CLAUDE.md 指令 | 中間推理和分析 |
| TodoWrite 任務清單 | 先前讀取的檔案內容 |
| Memory 檔案（`~/.claude/memory/`） | 多步驟對話上下文 |
| Git 狀態（提交、分支） | 工具呼叫歷史和計數 |
| 磁碟上的檔案 | 口頭表達的細微使用者偏好 |

## 最佳實踐

1. **規劃後壓縮** — 計畫在 TodoWrite 中定稿後，壓縮以重新開始
2. **除錯後壓縮** — 在繼續前清除錯誤解決的上下文
3. **實作中途不要壓縮** — 保留相關變更的上下文
4. **閱讀建議** — Hook 告訴你*何時*，由你決定*是否*
5. **壓縮前先寫入** — 壓縮前將重要上下文存入檔案或 memory
6. **使用 `/compact` 加摘要** — 新增自訂訊息：`/compact 接下來專注於實作 auth middleware`

## Token 最佳化模式

### 觸發表懶載入
不在工作階段開始時載入完整的 skill 內容，使用觸發表將關鍵字對應到 skill 路徑。Skills 僅在觸發時載入，減少 50% 以上的基線上下文：

| 觸發 | Skill | 載入時機 |
|------|-------|----------|
| "test"、"tdd"、"coverage" | tdd-workflow | 使用者提到測試 |
| "security"、"auth"、"xss" | security-review | 安全性相關工作 |
| "deploy"、"ci/cd" | deployment-patterns | 部署上下文 |

### 上下文組成感知
監控什麼在消耗你的上下文視窗：
- **CLAUDE.md 檔案** — 永遠載入，保持精簡
- **已載入的 skills** — 每個 skill 增加 1-5K Token
- **對話歷史** — 隨每次交換成長
- **工具結果** — 檔案讀取、搜尋結果增加體量

### 重複指令偵測
常見的重複上下文來源：
- `~/.claude/rules/` 和專案 `.claude/rules/` 中的相同規則
- 重複 CLAUDE.md 指令的 Skills
- 多個覆蓋重疊領域的 Skills

### 上下文最佳化方式
- `/compact` 指令 — Claude Code 內建的上下文壓縮
- 善用子 Agent 隔離大量搜尋結果，避免污染主 context
