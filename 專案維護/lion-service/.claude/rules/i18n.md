# i18n 多語系處理

> 多語系 key 的新增 / 對齊 / 補缺統一走 `scripts/i18n.py`，**禁止 Claude 直接 Edit / Write i18n 檔案**（`hooks/block-i18n-direct-edit.sh` 會攔）。
> 理由：避免 token 浪費（一次 add 要動 11 個 locale 檔）+ 避免 `.properties` `\uXXXX` escape 編碼踩坑。

---

## 1. 涵蓋範圍

### 1.1 後端（本 repo：cp-service）

```
cp-service/src/main/resources/i18n/
├── messages.properties          # default（zh-CN，reference locale）
├── messages_zh_TW.properties
├── messages_en.properties
├── messages_vi.properties
├── messages_ko.properties
├── messages_tl.properties
├── messages_ceb.properties
├── messages_id.properties
├── messages_in.properties       # Java legacy 碼，與 _id 同值雙寫（見 §2、§5）
├── messages_th.properties
└── messages_hi.properties
```

- key 慣例：`errorCode.NNNN` / `<domain>.<event>`；新增前先 grep 既有 key 的編號段
- value 為 **`\uXXXX` Unicode escape**（Java `Properties` 規範）；script 會自動轉
- locale 清單以 `scripts/i18n.py` 的 `BACKEND_LOCALES` 為準（本表若與 script 不一致，以 script 為準）

### 1.2 前端（不在本 repo）

前端 i18n 在 `lion-frontend`（`admin-frontend` / `agent-front` 等，子專案以實際目錄為準）與 `lion-manage`，**跨 repo**。

- 本範本不改前端；需求涉及前端文案 → 在 spec / plan 列「跨 repo 影響清單」（哪個前端專案、哪些 key），交由前端 repo 處理
- `scripts/i18n.py` 雖有 `add frontend` / `update frontend` 子指令（寫入同層 sibling 的 `lion-frontend`），**未經使用者明確要求不使用**

## 2. 強制走 script

```bash
# 新增 backend key（--zh-CN 必填；未給的 locale 以 zh-CN 值 fallback 並標 TODO）
python3 scripts/i18n.py add backend errorCode.9999 \
  --zh-CN "登录失败" --zh-TW "登錄失敗" --en "Login failed" \
  --vi "..." --ko "..." --tl "..." --ceb "..." --id "..." --in "..." --th "..." --hi "..."

# 修改既有 key 的值（只動有傳值的 locale）
python3 scripts/i18n.py update backend errorCode.1001 --zh-CN "新訊息"

# 對齊審查 / 批次補缺
python3 scripts/i18n.py audit --scope backend
python3 scripts/i18n.py fill-missing --scope backend
```

| 項目 | 規則 |
|------|------|
| key 已存在 | script 報錯擋住；要改值用 `update` |
| 缺翻譯 | script 以 zh-CN fallback + TODO 標記；**MR description 必列哪些 locale 是 fallback**，由人工補翻 |
| `id` / `in` | 印尼文要**同時傳 `--id` 與 `--in`（同值）**；script 把兩者當獨立 locale，不會自動同步，只傳一邊另一邊會變 zh-CN fallback |

## 3. Claude 操作規範（硬規則）

### ✅ 應該做

- 直接呼叫 `python3 scripts/i18n.py ...`，讀 script 輸出摘要
- 查 key 用 grep（不要 full read 整個 locale 檔）
- plan / spec 以「呼叫 i18n script」描述步驟，不要列「Edit messages_*.properties × 11」

### ❌ 禁止

- **禁止用 Edit / Write tool 直接改 i18n 檔案**
- **禁止用 sed / awk 批次取代 properties**（編碼會壞）
- **禁止用 Read 整讀 i18n 檔案**（單檔上千行，token 浪費）— 要查 key 用 grep
- 例外：script 本身有 bug → 告知使用者，經同意後手動處理單次，並記錄要修 script

### 子 Agent 規範傳遞

派子 Agent 處理涉及 i18n 的任務時，從 `rules/agents.md` §規範摘要對照 的「i18n 異動」列抄規範進 briefing 即可，**不需重貼本段**。

## 5. Java Locale 代碼（id ↔ in 等 legacy 映射）

Java `Locale.getLanguage()` 會把現代碼映射回 legacy（`id` → `in`、`he` → `iw`、`yi` → `ji`），與 DB / 前端用的現代碼對不上。

| 紅線 | 說明 |
|------|------|
| 取語言字串一律用 `I18nUtils.getModernLanguageCode(locale)`（lion-common） | 拼 cache key、寫 DB 欄位、對外 API 傳 language、與 DB 欄位比對時；**禁止** `locale.getLanguage()` |
| 建 `Locale` 用 `I18nUtils.getLocale(language)` | 不要 `new Locale(...)`，避免跳過既有 override |
| `MessageSource.getMessage(code, args, locale)` 直接傳 Locale 物件 | 例外，不需轉碼（bundle 依 legacy 檔名找，所以 `messages_in` 必須存在） |
| **全環境禁止加 `-Djava.locale.useOldISOCodes=false`** | 會讓各環境行為分歧（bundle 找不到 → 印尼文 fallback 成 default 中文） |
