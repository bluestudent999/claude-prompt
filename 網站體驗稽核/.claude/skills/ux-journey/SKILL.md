# ux-journey — 單一旅程深度檢視

**用法**：`/ux-journey <目標描述>`
範例：`/ux-journey 從首頁完成註冊並登入`、`/ux-journey 找到一場賽事並完成下注`、`/ux-journey 儲值 100 元`

**適用時機**：已經知道要看哪條流程（客服回饋集中在某一步、剛改版了結帳流程、想驗證某個轉換漏斗）。比 `/ux-audit` 便宜得多，比 `/ux-quick-scan` 深得多。

---

## Step 0 · Preflight

1. 確認 Chrome DevTools MCP 可用。
2. **確認環境模式**：這個 Skill 常涉及交易，模式判定特別重要。未指定且看不出是測試站 → **必問**（`scope-safety.md` §1）。
3. 需登入時確認憑證環境變數已設。
4. 建資料夾：`ux-reports/<YYYY-MM-DD>-<站點簡稱>-<旅程簡稱>/`（含 `findings/`、`journeys/`、`evidence/screenshots/`、`evidence/logs/`）。
5. 開起始頁確認可達。

---

## Step 1 · 定義這條旅程（輕量計畫，不調 `site-scout`）

你自己寫，**不需要完整的 `audit-plan.md`**。用 `templates/journey-spec-template.md`，30 秒內確定：

- **Persona**：誰在走？（一句話：認知水平 + 動機）
- **起點**：從哪開始？（預設從首頁，除非使用者指定）
- **成功條件**：看到什麼就算成功？（必須可判定）
- **交易處置**：`test` → 走到底的終點畫面是什麼；`production` → 停在哪一步
- **刻意試錯清單**：至少 3 項（`test` 模式）
- **視窗**：desktop 走完 + mobile 重走關鍵步驟

若使用者的描述不足以定出「成功條件」→ **提出一個並直接用**（例：「完成註冊」= 看到會員中心且帳號可再次登入），寫在紀錄裡讓使用者事後可校正。**不要為此卡住。**

---

## Step 2 · 走（調用 `journey-runner`）

調用 **`journey-runner`** 一次，傳入上面的旅程定義。

它會產出 `journeys/<id>.md`：逐步「我想 → 我看到 → 我判斷 → 我做了 → 結果」+ 卡點清單 + 手機端差異。

**走完後你自己補兩件蒐證**（`journey-runner` 專注在流程，這兩項由你收尾）：
1. **量測包**：流程中每個關鍵頁面 × 視窗抓一次（`observation-protocol.md` §4.5）。
2. **鍵盤走查**：對流程中的表單頁按 Tab 走一輪，記錄焦點順序與看不見焦點的元素。

---

## Step 3 · 評估

**平行**調用三個評估角色（id 號段：001-099 / 100-199 / 200-299），輸入是 `journeys/<id>.md` + 證據 + 量測包。

單一旅程的評估重點會集中在 `FRM`（表單）、`FBK`（回饋與錯誤）、`CTL`（可退出可撤銷）、`NAV-6`（點擊深度）、`TRS`（費用透明）。提醒各角色**特別留意卡點清單與「我判斷」段落中的猶豫**。

---

## Step 4 · 守門與報告

1. 平行跑 **`evidence-auditor`** + **`recommendation-reviewer`**，修正後重跑一次。閘門同 `/ux-audit` Step 4。
2. 調用 **`report-writer`**，告知這是單一旅程模式。

報告結構同標準，但：
- 「Journey 走查紀錄」是**主體章節**，要完整保留敘事。
- 「稽核限制」必須註明：只走了這一條流程，站上其他區域未稽核。
- 摘要要回答一個問題：**「這條流程順不順？痛在哪一步？」**

回報格式：

```
報告：<路徑>
旅程：<名稱> — <完成 / 完成但受阻 / 未完成>
實際步數：<n>（預估 <m>）
Finding：<總數>（Blocker n / Major n / Minor n / Suggestion n）
最痛的一步：<第幾步 + 一句話>
本次限制：僅稽核此流程
最該先修的三件事：1. … 2. … 3. …
```

---

## 這個 Skill 最容易漏掉的事

| ❌ | ✅ |
|---|---|
| 走順風路就交差 | 刻意試錯至少 3 項——錯誤處理才是流程 UX 的真正水位 |
| 送出後截成功頁就結束 | 還要截「處理中」，並回列表確認狀態真的更新了 |
| 只走桌機 | mobile 重走關鍵步驟（表單、送出、成功頁）——手機端問題通常更嚴重 |
| 標「完成」就當沒問題 | 實際步數超預估、有來回猶豫，都要開 Finding |
| 用網址跳到流程中段 | 從起點走。跳關就看不到入口找不到的問題 |
