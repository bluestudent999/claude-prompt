# Severity 判定與優先級排序

> **用途：** 統一 Severity 的判定尺度，並決定報告中「最該先修什麼」的排序。
> **核心原則：** Severity 描述**對使用者的傷害**，不是描述修起來多難。難易度放 `effort`。

---

## 1. Severity 判定表

判定時問一句：**「使用者會因此無法完成目標，還是只是不舒服？」**

| Severity | 定義 | 判準（符合任一即成立） | 上限 |
|---|---|---|---|
| **Blocker** | 使用者**無法完成**目標，或造成實質損害 | · 主要任務走不下去（按鈕無效、流程中斷、錯誤無出路）<br>· 資料遺失或重複扣款風險<br>· 整類使用者被排除（鍵盤使用者完全無法操作、手機版該功能不存在）<br>· 顯示錯誤金額／錯誤庫存等會導致錯誤決策的資訊 | 需 `confidence: High`（**Low 不得標 Blocker**） |
| **Major** | 使用者**能完成但代價明顯**，或明顯流失風險 | · 需繞路、重試、來回比對才能完成<br>· 錯誤訊息看不懂導致自行摸索<br>· 關鍵資訊（費用／條件）延遲揭露<br>· LCP > 2.5s、CLS > 0.1<br>· WCAG AA 明確不符（對比、focus、可及名稱） | — |
| **Minor** | **不影響完成**，但增加摩擦或降低信任 | · 一致性瑕疵、文案不精確、間距節奏亂<br>· 空狀態無引導<br>· 非關鍵頁的視覺破損 | — |
| **Suggestion** | 現況沒錯，但有**更好的做法** | · 可提升轉換或效率的優化提案<br>· 業界更成熟的互動模式 | 不得占報告半數以上 |

**降級檢查（避免虛胖報告）**

- 你能不能講出「哪種使用者、在什麼情境、付出什麼具體代價」？講不出來 → 降一級或刪掉。
- 只在極端條件下發生（特定舊瀏覽器、極端視窗、只出現一次無法重現）→ 降一級，`confidence` 降為 `Medium`／`Low`。
- 只有一次觀察且無法重現 → `confidence: Low`，且不得標 `Blocker`。

**升級檢查（避免漏掉真痛點）**

- 出現在**主要轉換路徑**上（註冊、登入、結帳、搜尋）→ 至少 `Major`。
- 影響**所有使用者**且**每次都發生** → 至少 `Major`。
- 手機端獨有的破損 → 不要因為「桌機正常」就降級；多數流量常在手機。

---

## 2. 優先級排序（報告的呈現順序）

報告的 Finding 依 **Priority** 由高到低排列。Priority 由 Severity × Effort 得出：

| | effort: S | effort: M | effort: L |
|---|:---:|:---:|:---:|
| **Blocker** | **P0** | **P0** | **P1** |
| **Major** | **P0** | **P1** | **P2** |
| **Minor** | **P1** | **P2** | **P3** |
| **Suggestion** | **P2** | **P3** | **P3** |

- **P0 — 立刻修**：擋住使用者，或投入極小效益極大。
- **P1 — 本迭代修**：明顯痛點，成本可接受。
- **P2 — 排入 backlog**：值得做，非緊急。
- **P3 — 有餘力再說**：改善型提案。

**同 Priority 內的次序**：
1. 位於主要轉換路徑者優先
2. 影響使用者比例高者優先
3. `confidence: High` 者優先
4. `effort: S` 者優先（快速見效）

---

## 3. Quick Wins（報告必備區塊）

從全部 Finding 中挑出 **`effort: S` 且 `severity ∈ {Blocker, Major}`** 者，單獨列成「Quick Wins」清單。

這是報告最有價值的一段——它回答了利害關係人真正想知道的問題：**「花最少力氣、今天就能改、馬上有感的是哪幾件？」**

若一條都沒有，誠實寫「本次無 Quick Wins，主要問題都需要中等以上投入」，不要為了填版面把 `L` 的事寫成 `S`。

---

## 4. Top 3（給決策者的一句話）

報告開頭必須有「**最該先修的三件事**」：從 P0 取三條，各一句話（問題 + 建議 + 預期效果）。

- 若 P0 不足三條，從 P1 補足。
- 三條要**分散在不同 category**（若可能），避免三條都在講同一個表單。
- 這三條的寫法要讓**不看技術細節的人**也能懂為什麼要修。

---

## 5. 記分（可選，使用者要求時才給）

若使用者要求一個總體分數，用以下方式計算並**明確標註這是相對尺度、非業界基準**：

```
扣分 = Blocker×15 + Major×6 + Minor×2 + Suggestion×0
總分 = max(0, 100 - 扣分)
```

同時給出各 category 的問題數分佈，比單一分數更有指導價值。**不要**憑感覺給分數，也不要拿這個分數跟其他網站比較。
